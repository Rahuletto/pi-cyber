## Concerns for the controller

1. **State vocabulary in the fail-fast message is bin-truthful, not optimistic:** when the state file says `validated`/`installed` but the binary is absent from PATH AND `~/.pi/tools/bin`, the guard reports that recorded state (`(state: validated)`) rather than downgrading to `cataloged` — the message then honestly tells the operator the state file has gone stale. The canonical uninstalled case still renders exactly `(state: cataloged)` as specified.
2. **`~/.pi/tools/bin` is an ADDITIONAL PATH segment, not a replacement:** a bin in that dir is ready even if the operator's `PATH` omits it (matches installer layout); spawn itself resolves through the runner's env snapshot, so the same resolution applies at exec time — a bin found by the guard is also spawnable by the runner (both read `process.env.PATH` at call time; the bin dir is the only divergence, which only matters if `~/.pi/tools/bin` is populated but is ALSO not on the child's PATH — the spawn would then fail with a surfaced `spawnError`; not silently lost).
3. **`interactsh` is registered per contract under the adapter name `interactsh`,** while its manifest/bin name is `interactsh-client` (the adapter registry already encodes this mapping; guard/message/render always use `adapter.bin`, so install.sh receives the correct manifest name). A user reading tool names sees `interactsh` — intentional, matches the task list verbatim.
4. **Row rendering reads `evidenceIds` from the JobResult against the most recent 50-row store window**, filtered by id (immune to concurrent writes), so for very large jobs the rendered slice is the window's most recent slice of THIS job with the loud all-rows-not-shown marker; the full evidence history stays behind `cyber_evidence` as designed, never auto-dumped.
5. **Env overrides `CYBER_TOOLS_STATE_FILE` / `CYBER_TOOLS_BIN_DIR`** are read at call time and documented as test/operator knobs (same pattern as `CYBER_EVIDENCE_DIR`). If neither is set, production behavior uses `DEFAULT_STATE_FILE` and `~/.pi/tools/bin` exclusively — no behavioral coupling to test envs in the default path.
6. **Per-call manifest reads:** each tool call re-reads `tools/manifest.json` (~2 KB) + `manifest.resolved.json` + the state file for the readiness check. Correctness over caching (fresh state every call); if this ever shows up in profiling, a TTL cache inside `binReadiness` is the one-place fix.
7. **No `timeoutMs` parameter on the per-adapter tools** (params are the adapter schema verbatim per the "reuse directly" ruling): jobs run at the runner default 120 s. The escape hatch remains `cyber_jobs` with an explicit `timeoutMs` for long scans; the per-adapter tools are the typed primary surface, `cyber_jobs` keeps the operator knobs.
