# Pi Cyber foundation implementation plan

Goal: build a locally reviewable Pi extension package while resolving browser and free-search choices. No Pi fork, global installation, target scanning, or browser binary download in this slice.

Architecture: thin typed Pi extension over a tested session-state module. Pi owns model execution and native compaction. Cyber mode, engagement scope, objective, coverage, evidence references, and next steps are durable session entries, restored with branch-aware recovery and injected into model context. Native tools remain available. Mode prompts are workflow guidance, not an operating-system sandbox.

Stack: TypeScript, pinned Pi 1.3.0 SDK, Bun tests, JSON themes and Markdown specialist definitions. Controlling spec: ../HARNESS-DESIGN.md; research instruction proposals. The existing scratch workspace is isolated and is not a Git checkout; no worktree or commit is needed.

1. Research CloakBrowser versus Obscura and free search/native compaction, using two independent research agents. Record primary sources and remaining runtime uncertainty.
2. Implement foundation through one implementation agent: package manifest, durable state, mode commands, structured state tool, red/blue themes, prompts, specialist templates, doctor, and behavioral tests. Write failing tests before behavior. Parent owns catalog and integration documentation; implementation agent owns package/src/tests/themes/prompts/agents/README.
3. Consolidate all existing candidate tables into one auditable inventory. Preserve source reports and distinguish candidate capabilities from installed executables.
4. Review spec and implementation quality with a fresh agent. Fix concrete findings, run focused tests and typecheck, and try the real SDK extension loader without model credentials.
5. Document exact local installation and remaining adapter/browser/search/worker integration work. Report what runs versus what remains a template or research choice.

Acceptance: session resume and branch recovery; mode changes while idle; active-work refusal; persistent state after compaction; no silent corrupt-state reset; native compaction unchanged; theme switch/headless behavior; state input validation; SDK typing and runtime extension-loading evidence. Doctor only probes PATH, never runs scanners. No credentials in reports.
