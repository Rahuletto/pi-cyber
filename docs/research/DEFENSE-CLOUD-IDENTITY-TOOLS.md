# Defense, cloud, identity, and exercise tool candidates

Research snapshot: 2026-10-21. This is a design shortlist for extending Pi as an orchestrator on an Apple Silicon Mac, not a claim that every tool is installed, compatible, or tested. The design supports two distinct operating modes: **Defense** for scan, triage, fix, and retest; **Authorized Offense** for scoped assessment and controlled adversary emulation. We used A-poc’s catalog across recon, execution, identity, collection, command-and-control, and other categories to discover candidates. Its README says the catalog mixes specialist and general-purpose tools; the catalog is an index, not an installation plan. [A-poc/RedTeam-Tools README](https://github.com/A-poc/RedTeam-Tools/blob/main/README.md)

**Compatibility labels:** “Documented Mac” means the upstream source explicitly documents macOS; it does not establish Apple Silicon support unless that is explicit too. “Mac client / remote target” means the operator can run from Mac while examining another system or cloud. “Foreign-host” means the collector/agent runs on the Windows/Linux/Kubernetes target, or that the product is built around that target platform. “Unclear” means the inspected primary source did not establish a Mac/arm64 path. No compatibility tests were run. We do not infer support from implementation language.

**Disposition:** Core = a good mode-specific default pack; On-demand = use when the role is needed; Reference = rules/data/specification or a library to feed another tool; Platform-limited = useful only with an identified foreign host, managed fleet, or lab. “Credentials” below means authorized, scoped credentials for the applicable engagement. Offensive tools can be appropriate in the Authorized Offense mode; they are separated from the Defense defaults because their purpose, target-platform needs, and effects differ.

**Evidence labels on each candidate:** *Source-reviewed* means I checked the linked upstream documentation or repository for the stated function/interface. *Catalog-only* means the candidate was present in A-poc’s catalog but current upstream capabilities were not validated in this pass. A-poc itself is a discovery index, not a compatibility test or an assurance of project maintenance.

## Minimal recommended packs and specialist roles

1. **Defense mode — Mac workstation core:** Semgrep, Trivy, osv-scanner, Syft, osquery, TShark, YARA, Sigma/pySigma. Add Gitleaks or Betterleaks after choosing a version line and normalizing report ingestion. Keep findings local by default; use scan-fix-retest workflows that return to the same artifact and evidence record.
2. **Repository and build supply chain:** CodeQL, Grype, Checkov, KICS, with pinned rules/query packs and SARIF/JSON artifacts. Keep cloud credentials out of these local scans.
3. **DFIR / log analysis:** Velociraptor for scoped Mac/endpoint collection; Chainsaw and Hayabusa for Windows EVTX; Volatility 3 only when a suitable memory image and matching symbols exist. Use Zeek/TShark on supplied PCAP; add Suricata on a supported Linux sensor path.
4. **Cloud and Kubernetes posture:** Prowler plus Steampipe for API-backed inventory/query; Checkov/KICS/KubeLinter for static files; kube-bench/kubeaudit only against a named lab or approved cluster with read-only permissions where supported. Use ScoutSuite as a multi-cloud report alternative, not a duplicate default.
5. **Identity assessment:** ldapsearch for focused directory queries; ldapdomaindump or Certipy for authorized scoped reporting; BloodHound CE plus SharpHound only when a Windows collection host is available. Treat graph/LDAP exports as sensitive personal and organizational data.
6. **Authorized Offense — application/network assessment:** Nmap, ZAP, and a curated Nuclei template set for named targets; use test accounts and engagement-approved windows. Metasploit is a specialist validation option, not a default scanner.
7. **Authorized Offense — purple-team lab:** Atomic Red Team for narrow endpoint telemetry validation; CALDERA or Sliver for planned emulation when the engagement calls for agents; Stratus Red Team in a scoped test account or an explicitly covered production account. Choose each exercise from the engagement plan and capture tool output, target, time, and cleanup state for the defense team’s retest.

Suggested specialist roles for Pi are **Source & Supply-Chain Reviewer**, **Cloud/IaC Posture Analyst**, **Mac Endpoint Triage Analyst**, **Windows Event/Timeline Analyst**, **PCAP & Network Detection Analyst**, **Directory/Identity Auditor**, **Web Application Assessor**, **Network Assessment Operator**, and **Purple-Team Validation Planner**. Keep Defense and Authorized Offense tools, prompts, and results in separate Pi modes with shared engagement metadata. A mode should inherit the authorized scope, target list, allowed techniques, accounts, time window, and stop conditions from the engagement record. This reuses the engagement authorization across its approved tasks; a new approval is needed only when the requested work exceeds that scope or introduces a material state change not covered by it.

**Evidence boundary:** this report documents upstream-described support and interfaces only. No packages were installed, no commands were run against targets, and no native Apple Silicon compatibility or end-to-end integration was tested. Where upstream documentation did not explicitly establish macOS/arm64, the table says so rather than extrapolating from the implementation language.
